# LOCOVE-FOUNDATION-DOMAINS-UI

## Goal 与当前交付边界

将 **Locove／洛湾** 做成可靠、轻量的本地服务查询与操作工作台：默认通过名称搜索、状态和实际地址一键打开；域名为用户主动启用的可选能力，按最新讨论采用高端口方案，默认实施值为 **5670**，首次需要系统解析配置时展示明确提示并取得当次管理员授权。

本轮在已有实现上完成 **D1–D5**：修复最新 review 的可靠性/交互问题，把网络件从默认安装与运行中移出，交付 `http://buildbase.locove:5670/zh` 一类可选入口，准备旧 80 系统件的安全迁移与卸载，完成真实环境与 UI 验收。不是从头重做最初的域名或 UI，也不是只保存计划。

本次 handoff 仅更新交接材料，未执行业务功能、系统安装、卸载或部署。接手者收到启动指令后持续实施到本轮范围验收。

## 1. 决策、建议与被替代的提案

### 已明确的用户意图与约束

- 品牌固定为 **Locove／洛湾**。工作台优先解决“方便查询”，支持快速找到服务、查看真实状态、打开/启动并打开、复制地址与查看日志。
- 尽量减少系统权限和常驻依赖；日常查询和管理不应以安装 DNS/Caddy/系统入口为前提。
- 用户最新讨论将域名能力与普通使用分开，提出高端口 **5670**、主动启用后才申请一次安装授权，并要求解释风险/影响；本 Goal 按这一可选路线交接。
- 本地 HTTP 为基础，不增加云端托管、远程控制面、云同步、遥测、公网 DNS 注册、HTTPS/CA/证书或 443 监听作为必需交付。
- UI 参考 **farion1231/cc-switch** 与 **yetone/magpie**。已有完整视觉重组可复用，本轮补可靠交互和按需启用 UI，不再把改名或地址 chip 当作唯一视觉交付。
- 用户未指定 ORX、PBV、多 agent、模型、预算或强制交付日期。

### 本轮采用的实施假设与建议

- 将 **5670 用作可选业务 HTTP 代理端口**，不是 DNS 端口，也不要求修改现有控制面 47800。数字由用户提议，尚非不可调整的协议常量；若占用/兼容性有证据，提供明确冲突和可配置端口，实际 URL 与设置保持一致，不静默换端口。
- 品牌域名路线优先采用稳定 `.locove` 后缀，服务名前缀可编辑。`buildbase.localhost:5670` 或三段 `.locove.localhost` 是可验证的免系统解析安装候选，不是本轮必须并行交付的模式；需要以目标浏览器实测决定。
- 任意后缀 `xxx.bcd`、反向命名 `loc.xxx`、将所有应用透明挂载到 `localhost:5670/xxx` 均只是讨论选项，未被确定为必交付功能。路径代理有资源/路由/HMR/同源兼容成本，不据此扩展通用重写平台。
- 保留 Python、launchd、AppKit/WKWebView 与已工作的 Caddy 实现；不以迁移 React/Tauri/Wails 或重选代理为开工前提。

### 与历史提案的关系

- 早期“域名地址必须完全无端口、需要 HTTP 80 入口”的基础验收已被本轮高端口/减权限方向替代。`http://buildbase.locove:5670/zh` 是本轮有效交付，不以旧书签兼容为由长期保留特权入口。
- 上一轮“整体归档域名”的建议未成为最终删除决定；本轮保留**可选、按需安装**，不默认删除域名定义或历史资料。
- 现行 V3.5 的“默认直连”继续保留；“关闭跳转但 DNS/代理/同步永远运行”的旧语义需要调整，不能只换端口数字或隐藏按钮。
- 初始 M1–M5、上次 C1–C5 的成功证据复用，最新未闭合项以 2026-11-05 review 为准。旧完成声明不替代本轮验收。

主要实施仓库仅为 `/Users/flb/Sources/Tools/LocalServices`：Python、Web UI、AppKit 壳、安装迁移脚本、schemas、CLI、Skill 的必要联动、测试和文档。Buildbase、ShiCha、UI-Atlas 等外部仓库默认只读，用作真实兼容样例；若必须修改其配置，给出最小改动的证据与路径后取得对应范围授权。

系统操作遵循实际平台授权机制。**主动启用域名是产品流程要求，不是提前授予后续 agent 任意 root、信任库或全局网络修改权限。** 先准备具体可审查的安装/迁移产物；首次实际安装需当次管理员确认，修复/卸载可能再次授权，不保存管理员密码或永久权限。取消授权继续直连；局部权限阻塞不阻塞隔离开发与普通功能。

必须保持：

- 服务源码、业务数据、登记、运行意图、日志与共享容器/卷；停止/退出 UI/迁移网络件不连带杀业务进程。禁止用顶层卸载脚本代替网络迁移。
- 幂等、revision、dry-run、人工覆盖、移除归档/恢复、导出脱敏；旧 TOML/endpoints 可读，不因换端口或关闭域名丢失声明。
- 未知进程不接管、不强停、不代理；已确认外部实例使用其实际端口。控制面 Host/Origin/token 与业务代理分离。
- 代理与 DNS 只回环；不接管全局 DNS 或普通网络流量，不为“可用”自动放宽系统/浏览器安全设置。
- 可选 Agent 识别仍只读生成候选，可能调用用户配置的云模型/网关；不宣称完全离线。手工登记与日常管理不依赖模型。

本轮不包含强制无端口、80/443 高级模式、HTTPS/本地 CA、任意私有/公网后缀产品化、LAN 分享、跨平台、完整路径代理平台或大规模技术栈改写。

## 4. 设计与用户流程

### 默认使用

普通安装 → 打开 Locove → 名称搜索/收藏定位 → 查看真实状态与原地址 → 打开或启动并打开 → 复制地址/查看日志。**不依赖 Caddy、不安装 resolver/系统 entry、不启动 DNS/代理/路由同步，不把未安装域名显示为故障。**

复用已有紧凑 UI 和搜索；修好 Enter/Space、按钮事件、日志选取/滚动与焦点。命令面板、最近使用统计、全局快捷键是可选优化，非必须追加系统级能力。

### 主动启用品牌域名

设置 → 查看 `http://buildbase.locove:5670/zh` 预览、端口和安装范围 → 确认启用 → 检查端口/依赖/既有配置 → 必要时取得当次授权安装仅 `.locove` 的 resolver → 普通用户启动 DNS/Caddy → 验证系统解析、代理和应用 → 才标为成功。

- Caddy 直接监听回环 **5670**，不经 80 转发器。DNS 沿用独立高端口；控制面独立，不能把 token/原生桥暴露给业务 Host。
- 统一生成含实际端口的 public_url，贯穿 UI/CLI/Skill/打开/复制/导出；host、打开路径和上游端口仍独立。不要各调用方拼出不同端口，也不改业务内部端口。
- 端口占用、Caddy 缺失、resolver 为他人所有、DNS/代理启动或验证失败均报告具体原因；不绕过失败直接保存启用成功，旧有效配置可诊断/恢复。
- 前缀编辑、移除/恢复、suffix/custom 来源保真；旧非 `.locove` 声明保持可读并说明限制，不据此接管任意公共后缀。
- 拒绝授权保持直连；不自动修改系统代理绕行表。实际代理环境阻挡域名时说明最小修复，涉及系统改动需单独确认。

### 提示、关闭与卸载

提示至少说明：实际地址含 `:5670`；安装/运行什么、为何授权、只处理哪个后缀、仅本机可访问、不安装证书/不上云；取消如何使用直连，以后如何卸载。可表达为：

> 启用后将通过“服务名.locove:5670”访问。需要安装仅针对 .locove 的本地解析配置，并启动仅本机可访问的 DNS 和代理。不会替换全局 DNS、安装证书或开放局域网访问。首次安装需要管理员确认；取消后可继续直连。

区分“未安装”“已安装但关闭”“启动中”“可用”“失败”“卸载中”，不能以一项跳转布尔值冒充系统安装状态。实现可简化，但用户必须看懂网络件是否运行、哪些配置仍保留。

- 关闭域名回到直连，停止该可选网络模块与激活循环；已安装 resolver 若保留须如实展示，停止 DNS 后的失败表现需验证，不把域名告警放进日常主视图。
- 独立卸载动作经当次授权只删除确认归属的配置。先修 S2，读失败或未知归属时拒绝删除。
- 日常启停不重复改受保护文件；不承诺首次安装后永不再需授权。

### 从现有 80 安装迁移

盘点开关/路由/用户 agents/系统 entry/resolver 归属及代理绕行修改，预览保留/移除对象。迁移动作切业务 URL 到 5670并验证，撤下仅属于 Locove 的 80 LaunchDaemon 与受保护脚本；resolver 按用户是否保留品牌域名决定保留/移除。

不为旧无端口书签长期保留特权 entry；告知旧链接需更新。缺管理员授权时可完成普通代码与直连功能，精确记录旧 entry 仍在，不能伪称 80 已退役。Caddy 二进制可能供其他工具使用，不无条件卸载包；代理绕行表只回收可证明由本工具增加且不覆盖用户后续修改的部分。
